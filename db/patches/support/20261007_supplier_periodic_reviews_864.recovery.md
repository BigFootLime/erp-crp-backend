# Évaluations fournisseurs — récupération

Sauvegarder les bases et la GED avant la migration additive. Arrêter le service ciblé, appliquer avec le runner canonique puis contrôler les privilèges et la disponibilité du service. Les programmes et évaluations sont immuables, sans effet sur les homologations existantes ni les agréments client. Aucun programme, score ou responsable n'est créé par cette migration.

Si le runtime échoue, restaurer sa release précédente en conservant les nouvelles tables. Le rollback de schéma est limité au programme encore vide. Après première saisie, utiliser une correction vers l'avant. Une correction d'évaluation conserve sa période, exige une nouvelle preuve approuvée et un motif ; l'ancienne version reste lisible. Les échéances décidées restent inchangées lors d'une modification de périodicité ; la nouvelle cadence propose la prochaine date lors de l'évaluation suivante.

La recette métier est différée jusqu'à la fin de l'objectif, sur instruction de Keenan. Les preuves de compilation ne constituent pas une acceptation métier.
