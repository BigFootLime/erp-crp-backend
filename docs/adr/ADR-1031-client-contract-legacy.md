# Explicit historical CADRE association — #1031

The client-owned contract is the authority for future firm calls. Existing CADRE orders are historical commercial records, not newly created calls. A user may explicitly associate a same-client CADRE with an active contract after reviewing its actual lines. No order, release, BL, OF, initial AR, stock quantity, OLD-stock provenance or quality approval is rewritten by this command.

Match actual article family IDs and a unique case-insensitive canonical unit code. Reject unknown articles, ambiguous families, incompatible units or a historical technical version that belongs to another article. Never infer identity from references, designations or the current technical index. A missing ordered technical version remains null; this commercial association grants no manufacturing or OLD-stock quality exception. Future demand still uses the current validated contract proposal.

The immutable association ledger retains contract/version, actual source/order/line IDs, canonical article family/unit, ordered technical identity, source snapshot/hash, actor, reason and request receipt. The preview exposes current source and, after association, its original recorded source. Existing permitted quantity/date edits do not overwrite this snapshot. Source IDs remain strings at the API boundary.

The command locks actor/key, client, contract, source order, release parents, order lines and articles in canonical order. It compares the expected contract version and exact source digest after locking. Parent order/release locking serializes existing canonical edits and child insertions. Database guards also protect historical order/client identity and line insert, move, delete or identity changes. New composition under an associated CADRE is refused; existing release status/date maintenance remains available.

Canonical BL guards resolve either the immutable firm-call binding or the explicit historical association. Unassociated CADRE orders retain their separate historical identity. A shared advisory transaction lock stabilizes BL boundaries; the rare association command acquires its exclusive form after source locks. Pending DRAFT/READY BLs are checked after insertion inside the same transaction; a now-incompatible BL rolls back the entire association. Shipped BLs and archived evidence remain unchanged. Existing client, destination, stock and quality gates remain authoritative. Dedicated proforma/payment isolation remains separate #1030 work.
