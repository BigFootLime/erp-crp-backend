# Empty quality execution cancellation (#1276)

CQ-2026-001311 was opened on the fictional LOT-2026-001310 using a published plan with an obsolete visa reference. Revising the plan correctly preserved the existing execution's snapshot. The pending-control guard then prevented opening the corrected version, with no way to cancel the erroneous empty workspace.

`POST /api/v1/qualite/v2/executions/:id/cancel-empty` requires the existing `release_decide` capability, the current revision and a trimmed reason of 8–1000 characters. It accepts only an open control with no measurement, measurement revision, decision or processed quantity. The source, population, frozen plan, hash and original executor remain unchanged. Cancellation records its own actor/date/reason, audit and business event. A same-reason retry returns the accepted cancellation; a different reason conflicts.

No release, rejection, non-conformity, stock movement or quality quantity is generated by cancellation. Cancelled controls remain readable, leave the pending-control lists, and reject subsequent measurement, decision, reopening or deletion. PostgreSQL locks serialize child evidence with cancellation. The nullable validation date stays null: cancellation is not a quality decision.

The execution detail adds `can_cancel_empty`, derived from the current execution and the existing request-level `release_decide` authorization. It is only a UI affordance: the cancellation command independently rechecks authorization, revision, measurements and decisions under locks. The client must not reproduce or broaden the role policy.
